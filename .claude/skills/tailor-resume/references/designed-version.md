# tailor-resume: optional designed version (creative fields only)

Part of the `tailor-resume` skill: step 8b, after the checked ATS PDF is made (its SKILL.md).

8b. Offer it only if the user's `field` or target roles are creative or visual (design, UX, marketing, advertising, communications, architecture, media, film, fashion, and similar) or they ask for "a nicer-looking" or designed resume. Say plainly: "Online application forms should get the plain version; the designed one is for emailing a person, sharing directly, or bringing to an interview." It is always made **alongside** the checked ATS PDF (SKILL.md, "Make the PDF"), never instead of it, and never before it.
   - Copy `profile/templates/resume-designed-template.html` (or, if the user has no copy there, `templates/resume-designed-template.html`) to `jobs/<folder>/resume-designed.html` and fill it with **exactly the checked `resume.md` text** (same bullets, order, numbers; no new claims, no summary that isn't in `resume.md`). If any wording differs from `resume.md`, run `truth-checker` on the changed lines first.
   - Its layout comes from `layout_designed` in `profile/design.md`: `sidebar` (experience and projects in the main column, a short tinted sidebar on the right: education, skills, certifications, languages), `headline` (one column under a bold name band, skills as tags) or `portrait` (a centered header with a photo slot above the same two columns as `sidebar`). All three use the same markup in the template's top comment: the main column comes first in the file and the short sidebar after it, so the PDF text reads the main column, then the sidebar. The `headline` line under the name is only for a summary or target-role line that `resume.md` already has, word for word; otherwise delete it.
   - **Photo (`portrait` only):** suggest `portrait` only when the user wants their photo on it and has chosen the photo themselves (AGENTS.md ground rule 4: never add one otherwise). Then uncomment `img.photo` in the header, with their photo file in the job folder as `src` and `alt="Photo of <their name>"`; without one the slot stays commented out. Remind them a photo suits sending to a person, and that employers in the US, UK, Canada and Australia usually expect none.
   - Same page target as the ATS version; check with `page-count.sh`. Then `bash .claude/skills/tailor-resume/scripts/make-pdf.sh jobs/<folder>/resume-designed.html "<First Last>" "<Company>"` (Windows without bash: `make-pdf.ps1` with the same arguments). It saves `<First>-<Last>-Resume-<Company>-Designed.pdf`; the ATS file name doesn't change, and the Apply Kit keeps offering the ATS PDF for uploads. Fix anything but `parse: ok` the same way as for the ATS PDF, and handle a `photo-note:` line as SKILL.md says (keep the photo only if the user chose it).
   - Run `page-review`'s "Theme and audience" checks on it (real text, nothing hidden, contrast on white). Manual fallback: Print → Save as PDF with **Background graphics on**.
