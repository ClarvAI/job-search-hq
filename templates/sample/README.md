# Sample data (Alex Rivera, made up)

A complete, fictional job search used only to fill a **separate sample workspace**, so someone can try the panels and pages before entering anything about themselves. Alex Rivera, every company, person, address and number here is invented (`example.com` addresses, 555 numbers).

- **Never copied into the user's own folder.** `.claude/skills/tour/scripts/make-sample.sh` (or `make-sample.ps1`) makes a new folder next to the user's workspace, named `<workspace name> (sample - Alex Rivera)`, copies the app into it, then fills its personal folders from `workspace/` here. The user's own workspace is never written to.
- `workspace/` is laid out exactly like the personal folders of a workspace (`profile/`, `jobs/`, `contacts/`, `outbox/`, `interviews/`, `history/`, `knowledge/field/`). Anything not here (the page look in `profile/design.md`, references, published pages, the work-search log, the pages themselves) comes from `templates/blank/` through the normal first-run script, so it always matches the current blank files.
- `page-data/` holds the JSON for the data blocks of the dashboard, the flashcards and the Acme interview brief. `make-sample` puts it into the sample's copies of the blank pages, so the pages keep the current design. No `<` anywhere in these files (D4).
- **Dates move with the calendar.** Text and file names use tokens that `make-sample` replaces on the day it runs: `{{D+3}}` / `{{D-12}}` = that many days from today as `YYYY-MM-DD`; `{{N-1}}` = the same as `YYYYMMDD` (lead ids); `{{UNCLEAR}}` = a slash date about a week out that could be read either way (like `11/03/2026`), for the one "date unclear" tracker row. So follow-ups are due today, an interview is tomorrow and an offer deadline is a few days out, whenever someone tries it.
- The data follows the same rules as real files: the CSV rules in `AGENTS.md` (byte-order mark, quoting, no cell starting with `=`, `+`, `-`, `@`), the tracker columns and statuses in the playbook, and the Outbox header rules. `scripts/ci/e2e-sample.py` (in a clone of the repository) checks all of it.
- The sample preferences say `SETUP: done` and `name: Alex Rivera (sample)`, and leave `date_order:` blank on purpose so one tracker row shows how an unclear date looks. No tracker row is `accepted`: that status turns the dashboard and the startup note into "wrap up your search" mode, which would hide everything else.
- This README is not copied.
