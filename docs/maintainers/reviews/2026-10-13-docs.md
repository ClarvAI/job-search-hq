### Risks found (not fixed; outside my files)

1. **Our Claude hooks may run in Cursor, Copilot CLI and Devin CLI.** The guard command is `bash "$CLAUDE_PROJECT_DIR/.claude/hooks/guard.sh" || { …; exit 2; }`. If those apps don't set `CLAUDE_PROJECT_DIR` (undocumented for Cursor), bash fails and the wrapper exits 2, which would **block every matched tool call** (shell, web fetch, MCP) in those apps, or the guard may misread their input format. Untested either way. Docs say "treat the check as not running".
2. **`CLAUDE.md` says the desktop built-in browser "keeps the user's sign-ins".** Anthropic's desktop doc: clean profile, none of your saved logins; Keep cookies is optional. Owner of CLAUDE.md should fix (Needs).
3. **AGENTS.md / SECURITY say Codex doesn't check apply_patch.** Codex hooks *can* match `apply_patch|Edit|Write` (learn.chatgpt.com/docs/hooks); our matcher just doesn't. User docs now say "this folder's check doesn't look at file edits", which is accurate.
4. **Gmail and Google Calendar connector docs say read-only** (claude.com/docs/connectors/google/gmail, …/calendar), yet the connector tools seen in a live session include `create_draft` and `create_event`. The docs keep "makes drafts"; a live check is still owed (HANDOFF §2).
5. **Claude Code auto memory is on by default** (~/.claude/projects/<project>/memory/), the Claude-side twin of what `.codex/config.toml` turns off. A project setting `"autoMemoryEnabled": false` exists (code.claude.com/docs/en/memory). Recommend adding it to `.claude/settings.json` (lead/owner decision); privacy.md would then say "this folder turns it off".
6. Hook time-out default is 600 s in both apps; this folder sets 30 s. Behaviour on time-out for Codex is undocumented.
