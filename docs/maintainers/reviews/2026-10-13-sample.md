# Try it first: the sample workspace (P1-15), 2026-10-13

Agent G. Scope: `templates/sample/**`, `.claude/skills/tour/**`, `scripts/ci/e2e-sample.py`.

## Design and why

**A separate sample folder, never sample rows in the user's folder.** `make-sample.sh` / `make-sample.ps1` (in `.claude/skills/tour/scripts/`) make a new folder next to the workspace, `<folder name> (sample - Alex Rivera)`, and the user opens that folder in the app (Claude: new session in that folder; Codex: add it as a project). Why this design rather than sample rows in the user's own files:

- D7 ("the tour never edits real data") and ground rule 1 are kept by construction: nothing is ever written inside the user's workspace, so sample data can't get mixed into a real tracker, contacts list or master resume, and there's nothing to clean up there afterwards.
- The panels, hooks, startup note and pages all read fixed paths (`jobs/tracker.csv`, `profile/preferences.md`, ...). A whole separate workspace is the only way to show them all working without a "demo mode" switch in each panel and hook.
- A copy is cheap (about 400 app files, 3 MB) and goes away with one command.

**Safety rules (both versions, all tested):** the target must not exist (mkdir without `-p`, so a race can't write into an existing folder); on a clash it prints `suggest: <name> 2`. It refuses a parent folder that is a link (never follows links), a target inside the workspace or holding it (resolved real paths, case-insensitive), a folder name with a path or `:` in it, and running from inside a sample (marker present). The app copy skips user-owned and local-only paths (mirrors `is_protected`), maintainer-only paths (mirrors `is_maintainer`), `.git`, links, `.DS_Store` and `~$` files. A marker `.sample-workspace` is written first. `--remove` deletes only a real folder (not a link) with that marker **and** whose preferences still say `name: Alex Rivera (sample)` (so a sample someone has typed real details into is never deleted), no `.git`, no open Excel lock, outside the workspace.

**Data stays current.** Sample files use date tokens (`{{D+3}}`, `{{N-1}}`, `{{UNCLEAR}}`) in text and file names, filled in on the day the script runs, so follow-ups are always due today, the Acme interview is tomorrow, the Initech Gmail draft has waited 3 days (due alert) and the offer deadline is ahead. Only the personal files the sample needs are in `templates/sample/workspace/`; the rest (design.md Default look, references, published pages, work-search log, pages) comes from `templates/blank/` via the sample's own `init-data`, so the sample never drifts from blank-file changes. Page data lives as JSON in `templates/sample/page-data/` and is spliced into the sample's copies of the blank pages, so pages keep agent A's current design.
