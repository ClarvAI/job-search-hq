## PN-13: Outbox attachments (Gmail drafts only)

Connector shape, from the Gmail connector's `create_draft` schema (read 2026-10-13 in this session): `attachments: [{ content (base64), filename, mimeType, inline? }]`, "The combined size of attachments in the message cannot exceed 25MB"; the result is a Draft with `id`, `threadId`, `viewUrl`. The engine's `$.fs.read(path, { as: 'bytes' })` returns `{ base64 }` and rejects files over 4 MiB.

What the panel does now (`.claude/skills/outbox/hooks/register.tsx`, `planAttachments`, `loadAttachments`, `viewUrlOf`):
- A draft "has an attachment" when its text says so (the existing wording check) or it names files in a new optional `attach:` header.
- The file must be a PDF in the draft's own job folder (`job:` header, one plain folder name): named in `attach:`, else the single finished `*-Resume-*.pdf` / `*-Cover-Letter-*.pdf` there that the text mentions (resume/CV, cover letter). Never a `-CHECK.pdf`, never a link (list entry or `$.fs.stat` `isLink`), never anything whose resolved path is not exactly `<workspace>/jobs/<folder>/<name>` (the folder itself must not resolve elsewhere), never below 3000 bytes, never over 4 MiB each or 10 MiB in all, never older than its `resume.html` / `cover-letter.html`, and more than one candidate means no guess.
- The confirm row says exactly what will be attached ("It will attach Alex-Rivera-Resume-Acme.pdf (82 KB) from jobs/acme-ops.") or why not, before anything is created. At confirm time the files are checked again (same name, size and time as shown), read as bytes, and must start with `%PDF-`. Anything off: the draft is made without that file and the panel says plainly what to attach by hand.
- Send mode never sends an attachment: such a draft's main button becomes **Create Gmail draft…** (with the file), never Send, and the card says so.
- After a draft is made, an **Open in Gmail** link shows when Gmail returns a `viewUrl` on `https://mail.google.com/` (any other address is ignored).
- Tests: `outbox/tests/attachments.test.tsx` (8 tests: shown then attached with Open in Gmail; two files and `attach:`; -CHECK only / no job folder / path traversal / a -CHECK name; link, outside path, too big, empty, out of date, not a PDF, ambiguous; job folder that is a link; file changed after it was shown; send mode makes a draft and never sends; a non-Gmail viewUrl shows no link) and the updated send-mode case in `outbox-flows.test.tsx`.

## Concurrency (P1-17)

The panel API has no file lock, so every save now refuses a file that changed since the panel read it:
- CSV panels (Pipeline, Contacts, Job Inbox, Apply Kit): each keeps the fingerprint of the file's text as last read (`sig` in its state); `saveRow` re-reads, refuses on a mismatch ("Your tracker changed in another app since this panel read it, so nothing was saved. The panel now shows the latest version: check it and try again."), compares again right before the write, and checks the saved row afterwards. The panel refreshes, so the next press works. The old behaviour (silently re-applying the change to the new version) is gone.
- Outbox: each draft carries the fingerprint of its whole file; Discard, Mark sent and Create Gmail draft/Send refuse any change, even a header line ("That draft changed or moved since this list was drawn").
- Tests: one per panel (`pipeline.test.tsx`, `apply-kit.test.tsx` updated; new cases in `contacts.test.tsx`, `job-inbox.test.tsx`, `outbox-flows.test.tsx`) plus the shared `saveRow` tests (changed before, changed between check and write, damaged, Excel lock, missing row, refusal, held file, lost save).
- Limit (unchanged, honest): two writers in the same millisecond can still collide; the after-write row check catches most of those and says so.

Paging already kept every panel under the 100,000-character draw limit (asserted in the perf tests).

## Sound (owner requirement)

Before: the Interview Room read every line aloud by default (`isVoice` default true, an unscoped stored value), and played a beep at think-time-over, 30 seconds left and time up whenever the clock was on. No other panel or the due-alerts pop-up played sound (they only use toasts; checked every `hooks/` file for `audio.`, `say`, `afplay` and System.Speech).

After: voice and sounds are off in every folder until the user presses **Turn on voice** / **Turn on sounds**, or Claude passes `voice: true` / `sounds: true` to `interview_start`, which the tool description allows only after the user said yes in chat. The choice is kept per folder (`voice:<root>`, `sounds:<root>` in the plugin store; the old unscoped value is ignored). **Turn off voice** is always visible while it is on and stops the reading after the sentence being spoken (the engine has no way to cut a sentence off). Notices still show without sound; the clock-off setting is independent. Tests: `interview-room/tests/consent.test.tsx` (silent fresh folder; button only; per folder; turning off mid-line; Claude's flag).

## Interview Room language

None installed: the default voice, and Claude and the user are told. Tests in `consent.test.tsx`.
